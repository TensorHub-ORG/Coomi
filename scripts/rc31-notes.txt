Coomi Beta 0.9.9-rc31：修复「添加厂商」报 HTTP 400（三条根因）＋ 失败现场留痕。

一、添加厂商报 400：接口类型取值与引擎对不上（主因）
· 向导的「接口类型」下拉以前发的是 openai / anthropic / gemini / custom，而引擎只认四个规范名 openai_compatible / openai_responses / anthropic_messages / gemini_native —— 新建厂商必然被拒（编辑老厂商因为回填的是规范值才侥幸能过）
· 现在下拉直接用引擎规范名，并多了一档「OpenAI Responses」；老配置里的历史值（openai / custom / anthropic / gemini）读进来时自动归一，不会再显示空白或被拒

二、模型上下文窗口越界
· 引擎只接受 32000 ~ 1048576，填 8192 这类小窗口以前是直接 400，且完全看不出是哪一格的问题
· 现在：输入时就地标红提示区间；保存时按区间夹紧，并在保存后明确告诉你「哪几个模型被改成了多少」

三、本地模型没有 API Key 被拒
· 向导固定发 activate=true，而引擎要求「激活前必须有 Key」——Ollama / LM Studio 这类本机服务全被堵死
· 现在：有 Key 才自动设为当前厂商；本机地址（127.0.0.1 / localhost / 0.0.0.0 / ::1）无需 Key 也能激活（引擎侧同步放行）
· 没填 Key 又不是本机地址时：先保存并在提示里说清「已保存但未激活」以及原因，不再弹一个看不懂的 400

四、错误不再是裸「HTTP 400」
· 引擎的四条英文错误（接口类型不受支持 / 上下文窗口越界 / 激活需要 Key / 模型列表为空 等）都会翻译成「该改哪一格」的中文，并附上引擎原文

五、失败现场留痕（排查用，新）
· 添加/编辑厂商失败时，界面会把「哪个操作 + 脱敏后的关键字段（类型 / 地址 / 模型数 / 有没有 Key / 会不会激活）+ 引擎原文」记一条
· 记录写在 %APPDATA%\Coomi\frontend-notes.log，并自动带进「环境诊断」文本（最近 8 条）—— 以后再遇到类似问题，一次就能定位，不必再靠复述
