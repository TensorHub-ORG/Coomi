Coomi Beta 0.9.9-rc32：修掉「添加厂商」在 rc31 里暴露出来的那道 400 —— 厂商标识为空。

一、根因：向导从来没给新厂商发过标识（id）
· 引擎的 providers 接口第一条校验就是「必须有 id」（它是 providers.json 的键，切换模型 / 拉取模型 / 删除都按它走）
· 而向导提交时写的是 id: editing?.id —— 新建厂商时它是 undefined，JSON.stringify 会把值为 undefined 的键整个丢掉，于是请求体里根本没有 id → HTTP 400 provider id is required
· 界面上「厂商标识」从来没有输入框（设置页只显示不可编辑），所以这个 400 是必然触发，不是偶发；以前被更靠前的报错挡在后面，rc31 修掉接口类型之后它就露出来了

二、改法（两侧都做，任何客户端都不会再撞）
· 前端：新建时按「厂商名称」自动生成标识（英文/数字 → slug；中文或纯符号 → provider-<时间戳后 6 位>；与已有厂商重名 → 自动加 -2、-3…），向导里新增一行只读的「标识（自动生成）」让用户能对上日志；编辑已有厂商时永远沿用原 id
· 引擎：客户端没给 id 时按同一套规则自行派生并把最终 id 回传（含单元测试：slug、中文回退、重名追加）

三、顺手修掉「一次只报一个错」
· 保存前本地先自检一遍，把所有问题一次列全（厂商名称 / 接口地址 / 标识 / 至少一个模型 / 上下文窗口越界提示），不再修一个冒一个
· 「厂商标识」相关的错误文案改成指向真正的原因（以前误写成「请填写厂商名称」，而界面上根本没有那一格可填）
· 保存失败的现场记录补上「有没有 id」这一项，方便下次一眼定位
