Coomi Beta 0.9.9-rc34：把「模型的输出质量」和「你看到的就是真的」这两件事做到底。

一、半截回答不再被当成完整回答（引擎根因修复）
· 根因：上游或代理在半途掐断 SSE（没发 [DONE]）时，引擎两个分支都返回「成功」——半截回复被当成
  完整答案收尾，界面上一个字都不会提示。rc33 修的是"前端终于会画那张可重试卡"，但触发条件本身
  还在：断流时 run_turn 返回的是 Ok，压根走不到发 retry_confirmation 的那一段。
· 现在：Chat Completions 路径上「没收到终止标记」一律判为未完成，返回可重试错误，
  于是一张「继续这一轮 / 重试」的卡片就会出现，而不是静默结束。
· 同时补上一次尾部残留解析：最后一帧没有换行时，结尾内容不再被丢掉。
· 另外四个适配器（Responses / Anthropic / Gemini / 远端压缩）各自的终止事件已经识别，本轮只做
  判定不强制，避免误伤。

二、压缩之后不再出现"假失败"
· 压缩是按预算逐条挑选的，可能出现「保留了带 tool_calls 的助手消息，却把它的 tool 结果丢掉了」。
  这种历史发给厂商会被判非法，引擎只好补一条合成的 "error: aborted"——等于告诉模型"这一步失败了"，
  于是它会重复已经完成的操作，或者干脆放弃。
· 现在压缩结果会做一次一致性收口：调用与结果要么都在、要么都不在。

三、长任务的上下文裁剪不会再卡死
· 裁剪循环里被删掉的合成 tool 消息会被 normalize_history 又补回来，形成「删掉→补回→状态不变」的
  原地打转；旧实现没有迭代上限，会一直占着那个 worker 不返回（表现就是"一直转圈"）。
· 现在加了进度判据与硬上限。

四、工具按需注入（终于接上了）
· 引擎里那套 ToolRouter（关键词 + 依赖拓扑 + Top-k + token 预算）早就写好了，但一直没有接线。
· 现在接上了：工具总数超过 24 个时才启用，核心工具（读写/编辑/检索/shell/计划/提问/技能/记忆）
  永远保留，一个都没匹配上就回退成完整清单 —— 宁多勿少，绝不把工具箱裁空。

五、界面呈现的就是真实发生的
· 壳里的 WebSocket 桥以前只有一条（"切会话即换"），于是桥模式下切会话会掐掉别的会话的推送 ——
  多会话并行在桥模式上根本不成立。现在**按会话多路复用**，互不影响。
· 桥启动失败以前只回调 onerror、从不 onclose，调用方也就不会重连 —— 一旦落到桥模式且握手事件
  丢了，界面会永久停在「与引擎的连接已断开」。现在失败路径统一收尾，重连照常触发。
· 桥不再吞掉分片帧（continuation frame）：以前那种帧直接落进空分支丢掉。

六、更新与打包
· 更新清单必须带 sha256：以前缺摘要时是「跳过校验并继续安装」，等于把「清单被换掉」直接变成
  静默安装任意 exe。现在缺摘要 = 拒绝安装，并且壳侧在启动安装程序之前会**自己再校验一次**，
  不再依赖前端是否校验过。
· 打包不再写死本机绝对路径：引擎与前端产物由 scripts/prepare-bundle.mjs 在打包前拷进
  apps/desktop，resources 只引用相对路径 coomi.exe 与 ui-dist。换机器、换目录都能构建。
· 版本号单一来源：tauri.conf.json 不再写 version，统一从 Cargo.toml 继承；设置页显示的版本与
  「检查更新」比较的版本从此是同一个值。
· 收紧了 WebView 的 CSP（之前是 null），并把 assetProtocol 的作用域收回到应用自己的插件目录。
· 清除了入库的明文凭据：生产服务器口令与多个 GitHub PAT 改为从环境变量读取。
  **这些凭据必须轮换** —— 它们已经进过仓库。

七、不常驻
· 关窗默认就是退出（引擎一起停）。它是个 Agent 工具，不是常驻托盘程序；
  需要「关窗后台继续跑」可以在设置里显式打开。

· 事件顺序门：引擎给每个事件都带了自增的 event_seq，前端以前完全不消费它 —— 断线期间
  的帧永久丢失，只能等一轮结束再回读正文。现在按 event_seq 做顺序门：重复帧直接丢掉（不再冒出
  重复气泡），发现缺口立刻向引擎请求补帧，并周期性确认（ack）让引擎裁剪队列。
  引擎侧同步补齐了 resync / ack 两个命令（此前 resync_from 与 acknowledge_through 都已实现，
  却没有任何调用点）。
· 轮次判重不再误判：以前用本地自增的 turnSeq 判断「turn_end 是不是重复」，但排队/插话这两条分支
  在处理后提前返回、不递增它 —— 两条排队消息若在 1.5 秒内相继结束，第二条会被当成重复，
  于是轮次少计、完成通知丢失。现在改成以「本轮是否真正开始」为唯一依据。

八、其他
· 大文件预览/下载不再占死引擎的工作线程（整文件读取移入阻塞线程池）。
· 中文文件名下载不再触发 handler panic（Content-Disposition 按 RFC 5987 编码）。
· 富预览与文本预览不再「先整份读进内存再判断大小」：先看 Content-Length，缺失就流式计数、超限即中止。
  文本预览仍保持"截断并标注"的既有语义，不会变成打不开。
· 超时的直达请求现在会真的被 abort，不再泄漏挂住的连接。
· 新增本地任务级轨迹 trajectory.jsonl（每轮一行：成败/轮次/最后在用的工具/耗时/提示词指纹）。
  只在本地、不外传、不记提示词原文，可用于定位「模型在哪类任务上系统性做砸」。
