Coomi Beta 1.0

这一版三件事：**更省钱（缓存）、更能发挥模型实力、把「工具现在在干什么」看见**。

────────────────────────────────
一、更省钱：把 KV-cache 吃满
────────────────────────────────
· **工具集在会话内冻结**。工具定义属于提示前缀的一部分 —— 之前"按需注入"是每轮按提问重算，
  等于每轮都把自己的前缀缓存作废（多花钱、多等首字）。现在每个会话只决定一次，
  只有当"可用工具总数"变了（装了新 MCP/技能）才重算一次。
· **缓存命中率默认可见**：右侧「用量」里直接显示命中率与本轮命中率。命中率高 = 同样的前缀
  被复用 = 更省钱也更快。供应商没提供这个数据时显示「未提供」，不会假装成 0%。
· **项目大纲只算一次**：同一会话复用同一份字节，不每轮重算。

────────────────────────────────
二、更能发挥模型实力
────────────────────────────────
· **四条接口路径全部强制结束校验**。之前只有 OpenAI 兼容（Chat Completions）那条会
  检测"上游半途断流"，另外三条（Responses / Anthropic / Gemini）仍会把半截回复当成
  完整答案 —— 模型的能力被静默吞掉。现在四条一致：没等到结束标记就报可重试错误。
· **周期性复述目标**。模型在几十次工具调用之后容易忘记最初要干什么，转而去优化眼前的子问题。
  现在每 6 轮会把「原始目标 + 还没完成的计划步骤」重新推回上下文尾部
  （Claude Code 早期也这么做）。允许改计划，但不许把原始目标丢掉。
· **失败痕迹优先保留**。上下文压缩时，含失败的「调用 + 结果」对会被优先留下 ——
  模型靠这些痕迹更新判断、避免重复犯错。压缩后不会出现"有调用、没结果"的悬空历史。
· **项目大纲**。每轮带上当前工作目录的骨架（目录、文件类型分布、体积最大与最近改动的文件），
  省掉第一轮盲目的 list_dir/grep。它只是一份骨架，具体内容仍由模型自己检索决定。

────────────────────────────────
三、工具清单更清晰
────────────────────────────────
· 去掉了三个**执行路径完全相同**的重复工具名（search / fetch / request_user_input），
  模型少一个要考虑的选项；旧名字在执行层仍然有效，技能与插件里的引用不会失效。

────────────────────────────────
四、技能中心新增「任务」页
────────────────────────────────
· 技能中心顶部多了一个「任务」子页：能看到**正在安装 / 正在使用**的工具与技能任务，
  状态、进度、日志一目了然；运行中的可以取消，失败的可以重试。
· 需要参数的任务可以在同一个页面里**直接填参数**并提交，不用再回到原来的对话框去找。

────────────────────────────────
五、轨迹回放（设置 → AI 能力）
────────────────────────────────
· 每一轮任务的留痕现在可以在界面里看了：时间、成败、失败类型（上游截断 / 工具轮次耗尽 /
  引擎异常 / 上游不可用 / 工具报错）、用了几轮、最后在跑的工具、耗时。
· 可以导出成 JSON，方便发给我们定位问题。这些数据只存在你本机，不会上传。

────────────────────────────────
六、界面优化
────────────────────────────────
· 加载态统一走骨架屏；空态文案统一；数字列对齐与长文本溢出做了修正。

────────────────────────────────
七、升级提示
────────────────────────────────
· 上一版（rc35）修好了主题插件的资源加载（assetProtocol 作用域）与插件页的 CSP。
  如果插件页仍然是空白但主题图片正常，请把开发者工具里的报错发我 —— 那说明 CSP 还差一项。
· 本版起版本号进入 1.0 系列：1.0.0-beta.1。
