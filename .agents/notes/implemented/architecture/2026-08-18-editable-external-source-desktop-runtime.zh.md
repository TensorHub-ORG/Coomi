# Agent Note: 可编辑外部源码桌面运行时

Status: implemented

[English](2026-08-18-editable-external-source-desktop-runtime.md) | 中文

## 问题

如果桌面安装包内置一份已经构建的 Coomi 服务端与工作区，每次修改 agent、插件或客户端都要重新封装应用。用户无法像操作普通 Git 源码目录一样检查或编辑已安装的运行时，本地定制也缺少一个稳定基础，无法让其他工具针对它分析或合并 diff。封装整个工作区还会让桌面外壳拥有一批它并不直接执行的代码。

## 决策

Windows 安装包是带固定版本 Node 和 pnpm 运行时的轻量 Electron 外壳。它不包含 Coomi server payload、`apps/`、`packages/` 或 `vendor/`。外壳运行一份由用户选择的外部 Git 源码目录，并把解析后的路径、基础 commit、仓库和分支写入 schema 版本为 1 的 `%APPDATA%\Coomi\desktop-runtime.json`。

现有源码目录只有在包含根 package 与 lock 文件，以及源码启动所需的 CLI 源码、已构建 Web 入口和 `tsx` 依赖时才会被接受。设置窗口可以把官方 `coomi-desktop` 分支克隆到用户选择的父目录，并使用安装包内工具链安装依赖、执行构建。源码 CLI 按照[源码启动决策](2026-07-29-coomi-source-launch-tsx-esm.md)通过 `node --import tsx/esm` 启动，并使用隔离的 `%APPDATA%\Coomi\home` 作为 `COOMI_HOME`。

Electron 进程拥有源码服务与客户端包轮询 watcher 的子进程树。它等待 loopback 服务和插件 UI 就绪后才显示窗口。客户端冷启动报告插件激活失败时，外壳会先以全新导航重试，再显示设置恢复界面；watcher 只在客户端成功启动后运行，因此首次重建不会与初始插件激活重叠。

托盘提供打开源码目录、切换源码目录、重启运行时和创建源码检查点的操作。检查点把相对已记录基础 commit 的完整 diff（包括未跟踪文件）写入 `%APPDATA%\Coomi\changes`，且不修改源码目录的暂存区或工作树。它是分析产物，不执行自动合并，也不替代源码备份。

## 曾考虑的替代方案

**内置生产工作区 payload。** 拒绝，因为它会把插件与 UI 代码冻结在安装包中，重复保存已选源码目录，并要求每次本地迭代都重新封装。

**运行全局安装的 `coomi` 命令。** 拒绝，因为命令解析与依赖版本会取决于可变的机器状态，而不是外壳选定的源码目录和固定启动器。

**把 Electron 当作 Node 运行时。** 拒绝，因为 `ELECTRON_RUN_AS_NODE` 会把源码进程与 Electron 的运行时行为绑定。安装包内的 Node 可执行文件让源码启动命令保持显式，也让 pnpm 使用同一个固定引擎。

**加载客户端前启动 watcher。** 拒绝，因为全仓库首次重建可能在初始 Cordis 插件图激活期间替换客户端 bundle。推迟启动仍允许首次稳定渲染后的实时编辑，同时不会暴露冷启动竞争。

## 后果

用户只需安装一次桌面集成，并直接拥有可编辑源码目录。插件与客户端修改仍对 Git 可见，也能在应用运行时重新加载；检查点为后续分析或合并提供相对已记录基础版本的稳定 diff。

所选源码目录是可执行代码，因此具有与从终端启动它相同的信任要求。它占用自己的磁盘空间，并且必须保持结构准备完成。首次准备和 watcher 首次构建会消耗时间与 CPU，而安装包大小不再随工作区规模和源码变更增长。源码更新、冲突解决与备份仍是显式的用户或 Git 操作，不由桌面应用隐藏执行。
