# Agent Note: 桌面展示与运行状态

Status: implemented

[English](2026-08-17-desktop-presentation-and-running-status.md) | 中文

## 问题

Windows 外壳沿用了原生标题栏,其左侧会在应用自身的品牌页头之上重复显示产品图标和名称。固定深色会在窗口失去焦点时变化,也不会跟随 Web 主题。把该标签替换为完全空白的拖动条后,有用的标题栏空间仍空着,品牌行则重复占用下方空间。打包图标和应用内图标还在标志周围带有白色方块,因此与相邻透明图标显得割裂。

会话在整个运行中轮次里只显示一条通用英文活动文案。它没有 Coomi 身份,并且在长时间等待时显得静止,即使耗时仍在继续增长。

## 决策

Windows BrowserWindow 使用 Electron 隐藏标题栏样式和 38px 原生 window-controls overlay。preload 在 document 布局中预留同样的 38px,以 Web 主题 token 绘制该区域,并通过底部分隔线将其与工作区区分。侧边栏的既有字标与收起控件进入该区域左侧,其余表面仍可拖动;按钮退出拖动区域,右侧的最小化、最大化和关闭仍由 Windows 拥有。展开行使用 Coomi 标志、紧凑的 display 字体名称与独立收起控件。收起行只保留标志作为点击目标,悬浮时不会显示另一个图标或提示。该行跟随侧边栏宽度和收起动画,因此标题栏与栏位保持同一对齐线。每次主题呈现更新后,preload 读取 body 的最终背景色和前景色,再经一条私有 IPC channel 发送这两个 CSS 颜色。当页面存在 aria-modal 对话框时,preload 会发送对话框遮罩色,让原生控件区与 Web 标题栏采用同一模态处理。主进程只接受当前窗口的值,验证其 CSS 颜色语法,并在不引入 active/inactive 两套颜色的情况下更新 overlay。

桌面 PNG 与 ICO 资源、Web favicon 和应用内栅格图都使用透明外部画布,同时保留 Coomi 标志所包围的白色区域。ICO 从同一源图生成标准 Windows 应用尺寸,因此快捷方式、安装器 chrome 与渲染出的品牌界面共用同一标志并保持一致缩放。

轮次运行期间,ChatView 会在挂载时随机选择一条产品自有的中文 Coomi 活动文案,此后每四秒随机换成一条不同文案,并排除连续重复。状态仍是 polite live region;既有耗时继续以持久 `turn/start` 时间为起点,并在 15 秒后出现。文案选择只属于展示,既不写入日志也不恢复,因为它不会进入模型,也不描述会话状态。

## 验证

ChatView 组件套件固定初始随机选择,推进轮询计时器,并证明下一条文案不同,同时保留既有耗时与工具行行为。Web 交互场景会在实时轮次中定位产品自有状态。桌面验证在 Windows 上启动打包应用,检查快捷方式图标、标题栏间距、原生控件、焦点行为和浅色／深色主题颜色。

## 曾考虑的替代方案

**构建完全自绘的无框标题栏。** 拒绝,因为这样只为移除左侧标签就要复制 Windows 标题按钮行为、键盘与无障碍语义、贴靠集成和 hover 状态。Electron overlay 已经保留这些操作系统行为。

**保留一种固定标题栏颜色。** 拒绝,因为应用支持浅色、深色、跟随系统和已注册主题。单独的桌面调色板会与实际 Web 背景漂移。

**只把运行文案替换成一条本地化文本。** 拒绝,因为这样虽然恢复了 Coomi 命名,却仍保留静态的长等待展示,无法实现所给文案集合的目的。

**把所选文案持久化到 Session 日志。** 拒绝,因为该文案是瞬态展示文本,不承载会话事实,也不会进入模型。持久化会让随机 UI 装饰成为回放兼容内容。

## 后果

桌面窗口把应用品牌与侧栏控件放在原本可用的标题栏区域,将其与工作区内容分隔,保留 Windows 原生控件,跟随所选主题和模态状态,并让品牌图像不再带有不透明外部方块。运行中轮次会明确表现为仍在活动,使用 Coomi 专属文案,同时保留准确耗时与无障碍语义。

preload 由此承担一小部分桌面专属布局和 IPC 职责。第三方主题必须把 body 背景色与前景色解析为桌面验证器接受的 CSS 颜色语法;不支持的值会保留最近一次有效标题栏颜色。随机活动文案会有意在不同挂载之间变化,不属于回放证据。
