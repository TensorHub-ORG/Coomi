# 自动化工作流

工作流把工具、脚本、模型和人工审批组织为有依赖关系的步骤。入口是应用内「自动化工作流」，可以从模板创建，再在详情页编辑 JSON、运行设置和定时规则。

## 运行与结果

- 当前按依赖顺序逐步执行。同一工作流只能有一个活动运行，最多两个不同工作流进入执行，其余排队；内置工具仍遵循共享的执行互斥规则。
- 每次「立即运行」从第一步开始，产生独立运行记录。运行时冻结定义和子工作流，编辑只影响下次新运行。
- 直接工具步骤报错、命令非零退出、超时或审批拒绝都会使步骤失败，停止后续步骤。模型可在权限允许的范围内修正普通工具错误，但用户拒绝审批后即停止。运行历史保留各步的结果、错误、尝试次数和耗时。
- 支持 `tool`、`script`、`model`、`sub_workflow`、`approval`。模型步骤使用已配置的供应商、项目指令、内置工具和已启用 MCP；用量进入运行历史及现有用量账本。启动前检查所需模型配置。
- 模型步骤默认共享本工作流内之前模型步骤的上下文，设置 `model_isolation: true` 或步骤 `isolate: true` 可隔离。模型最多执行 96 轮工具调用。

## 工作目录、权限与时限

`cwd` 为空时使用引擎当前工作区，也可以设置存在的工作目录；运行开始时解析并固定。Android 沿用现有 RuntimePathMap 和 Linux 运行时，桌面开发环境使用平台 shell。内置巡检模板面向 Android/Linux，Windows 自定义脚本应使用 PowerShell 语法。

| 权限 | 行为 |
| --- | --- |
| `ask`（默认） | 修改和命令执行前等待确认；读取自动执行 |
| `auto` | 一般工具自动执行，触发现有安全策略的操作等待确认 |
| `full` | 自动批准工具调用；仍遵循工具的拒绝规则 |

人工 `approval` 节点始终等待确认。子工作流作为一组复用步骤，继承最外层运行的目录、权限和控制状态；单独运行时使用自己的设置。子工作流不单独触发定时，启动前检查递归调用。

步骤顶层 `timeout_s` 设置执行时限，默认 1800 秒，范围 1–3600 秒。脚本也兼容 `action.timeout_s`；直接 `shell` 步骤兼容旧 `arguments.timeout_s` / `timeout_ms`，顶层设置优先。审批、补充信息及已生效的暂停不消耗步骤时限；历史耗时包含等待时间。模型内部单次 `shell` 仍遵循该工具自身的时限，长命令应使用 `local_shell`。

直接命令步骤会等待进程退出才结束，`local_shell` 只接受 `exec`。模型可在同一步内启动、等待、写入或终止自己拥有的 shell 会话；这些会话不会跨步骤保留。命令环境仅接受 `auto` / `proot`。

`retry` 表示额外尝试次数，最大 10。目前只对 `fetch` 的网络失败、HTTP 429 和 5xx 自动重试；命令、写操作及未知工具失败后需要人工核对后恢复。

## 暂停、停止与恢复

- **暂停**：当前命令或工具执行完后，在下一安全边界暂停；模型在下一次请求或工具调用前暂停。界面会先显示「等待安全暂停」。
- **停止运行**：结束本次执行并清理其拥有的受管命令进程。已完成的文件改动、已提交到外部服务的操作保留。
- **引擎重启**：之前的活动运行标记为「已中断」，不自动重放；原有审批请求失效。
- **恢复未完成步骤**：适用于失败或中断的运行。先核对最后一步的实际产物，再确认恢复；系统创建新的运行记录，保留成功步骤，使用当次冻结的定义。未完成的工具/命令步骤重新执行，模型步骤参考已保存会话继续。操作完成与保存状态之间可能中断，因此不能保证外部副作用只发生一次。

运行历史最多保留 50 条，包含恢复所需的步骤和模型会话检查点。旧版运行没有检查点时，需发起新运行。

## 定时

使用五段 cron（分钟、小时、日、月、星期），按引擎本地时区判断，每 15 秒检查一次。模板创建后默认不启用定时，建议手动验证后开启。定时要求引擎持续运行；关闭期间的时间点不会补跑。同一分钟内避免重复触发，正在运行的工作流不会叠加启动。定时执行遇到审批仍会等待人工处理。

## 定义示例

下面是「读取文件 → 模型总结 → 人工确认 → 写入报告」的完整示例。先确保工作目录中有 `input.txt`，并配置可用的模型供应商。可用于 `POST /api/workflows`，也可在详情 JSON 中保留现有 `id` 后替换其他字段。

```json
{
  "id": "file-summary",
  "name": "文件总结",
  "permission": "auto",
  "model_isolation": true,
  "schedule": { "enabled": false, "cron": "0 9 * * *" },
  "steps": [
    {
      "id": "source",
      "name": "读取输入",
      "action": { "kind": "tool", "tool": "read_file", "arguments": { "path": "input.txt" } }
    },
    {
      "id": "summary",
      "name": "总结内容",
      "depends_on": ["source"],
      "timeout_s": 600,
      "action": { "kind": "model", "prompt": "用中文简要总结以下输入，只输出总结：\n{{source}}" }
    },
    {
      "id": "review",
      "name": "人工确认",
      "depends_on": ["summary"],
      "action": { "kind": "approval", "prompt": "确认将此结果保存到报告：\n{{summary}}" }
    },
    {
      "id": "report",
      "name": "保存报告",
      "depends_on": ["review"],
      "action": { "kind": "tool", "tool": "write_file", "arguments": { "path": "reports/summary.json", "content": "{{summary}}" } }
    }
  ]
}
```

`{{步骤id}}` 传递该步骤的完整结果；字符串直接插入，对象转成 JSON。也可从顶层 `variables` 提供输入值。只做一次替换，不支持点路径、表达式或条件模板；变量名避免与步骤 id 相同。

## 控制 API

| 接口 | 请求体 |
| --- | --- |
| `POST /api/workflows/{id}/run` | 创建新运行 |
| `GET /api/workflows/{id}/runs` | 读取状态、结果和待处理请求；不返回内部会话检查点 |
| `POST /api/workflows/{id}/runs/{run_id}/action` | `{"action":"pause"}`、`resume`、`cancel`；恢复需 `{"action":"recover","confirm_replay":true}` |
| `POST /api/workflows/{id}/runs/{run_id}/answer` | 审批：`{"request_id":"…","allow":true}`；回答：`{"request_id":"…","answers":{"问题id":"答案"}}` |

当前版本未提供条件分支、节点并行、拖拽编排、文件改动回滚和外部事务补偿。
