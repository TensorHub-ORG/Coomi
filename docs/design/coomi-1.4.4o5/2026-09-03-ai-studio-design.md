# Coomi 1.4.4o3：DeepSeek 模型接入修复与 AI 工作室设计

## 目标

在保留 Coomi 1.4.4、现有增强样式、DeepSeek 账号登录和附件卡片的基础上：

1. 登录 DeepSeek 成功后，使用账号协议保存并激活 Provider，不再错误调用通用模型发现接口。
2. 允许用户选择 DeepSeek 官方 App 的 Chat 或 Reasoner 模型。
3. 让对话页顶部模型栏及其弹窗真正相对屏幕居中。
4. 在控制台“进入对话”和“重启引擎”之间增加 AI 工作室，提供可持久化的多智能体群聊协作。
5. 版本升级为 `1.4.4o3`。

## DeepSeek Provider 修复

DeepSeek 账号 Provider 使用 `chat.deepseek.com` 私有账号协议，不支持 OpenAI 风格的 `/models`。登录成功后，前端调用一个专用引擎接口保存固定模型目录：

- `deepseek-chat`：普通对话。
- `deepseek-reasoner`：深度思考。

专用接口写入 Provider 配置并设为当前 Provider，不执行通用凭据验证和模型发现。登录页显示默认模型选择，已登录状态也允许切换；切换调用现有受控模型选择逻辑，但对 DeepSeek 账号 Provider 跳过 `/models`，仅校验登录 token 是否存在。

## 对话模型栏居中

顶部栏使用三列布局：左侧操作区、绝对居中的模型区、右侧操作区。模型选择弹层挂到 viewport 级固定容器，使用 `position: fixed; left: 50%; top: 50%; transform: translate(-50%, -50%)`，并限制安全区与最大高度。左右按钮宽度变化不再影响模型栏或弹层中心。

## AI 工作室架构

### 数据模型

工作室持久化在 Coomi 私有目录：

- Studio：id、名称、说明、共享工作目录、主持成员 id、创建/更新时间。
- Member：id、名称、头像、Provider、模型、职责、系统提示词、工具权限、状态。
- WorkItem：id、标题、说明、负责人、状态、依赖、结果摘要、时间线。
- StudioMessage：id、发送者、正文、@对象、关联工单、时间、消息类型。

状态：

- 成员：待机、思考、执行、等待、完成、失败。
- 工单：待处理、进行中、待验收、完成、失败。

### 协作模式

采用混合模式：

- 普通目标交给主持智能体。主持人根据成员职责拆解任务、创建工单、指派成员，最后验收并汇总。
- 用户输入 `@成员名` 时优先直达对应成员；成员完成后结果仍回到群聊和主持人上下文。
- 成员可以在输出中 `@其他成员` 请求协助；引擎限制最大转交深度和每轮最大调度次数，防止无限对话。
- 所有成员共享工作室目录。工具调用按成员独立权限执行；写操作记录到工单时间线。

### 引擎接口

提供 REST 管理接口和工作室 WebSocket：

- 列出、读取、创建、更新、删除工作室。
- 创建、更新、删除成员。
- 创建和更新工单。
- 读取消息与执行日志。
- 连接工作室、发送目标、@成员、停止当前协作。

引擎负责状态机、持久化和模型调用。前端只显示状态并发送用户动作，不在浏览器内模拟协作。

### 调度流程

1. 接收用户消息并解析 @目标。
2. 无明确 @时交给主持人；主持人返回结构化派单决定。
3. 引擎校验目标成员、模型、工具权限、依赖和并发上限。
4. 独立执行成员回合，把中间状态、工具事件和结果广播到群聊。
5. 工单进入待验收后交给主持人审核；通过则完成，否则附带反馈返工一次。
6. 所有工单终结后主持人给出最终汇总。

失败时保留已完成结果；单成员失败不会清空整个工作室。用户可重试工单或停止协作。

## 前端界面

控制台新增“AI 工作室”入口，位置固定在“进入对话”和“重启引擎”之间。

工作室包含：

- 列表页：名称、成员数量、运行状态、最后活动时间。
- 配置页：名称、共享目录、主持人，以及成员完整独立配置。
- 群聊页：顶部横向成员状态条，中部消息流和工单卡片，底部附件、@选择与输入框。
- 工单看板：按状态分组，点击查看负责人、依赖、流转时间线、工具摘要与结果。

视觉沿用 Coomi 当前简洁界面，使用现有颜色变量、图标和卡片规范，不复制示例图片的仓鼠品牌。

## 安全与边界

- Provider token 不进入工作室消息或前端持久化。
- 每个成员工具权限由引擎强制执行。
- 默认限制并发成员数量、每轮转交深度和最大模型回合。
- 工作室文件访问限制在配置的共享目录及既有安全策略允许范围内。
- 删除工作室需要确认；停止运行不会删除记录。
